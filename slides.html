Parameters vs Arguments

The Core Difference
🍰 Analogy: Baking a Cake
When you write a recipe, you write:

"Add [X] cups of flour, [Y] eggs, and [Z] teaspoons of sugar."

The X, Y, Z are parameters — they're placeholders. The recipe doesn't know yet if it's 2 cups or 5 cups.

When you actually bake, you decide:

"Add 2 cups of flour, 3 eggs, and 1 teaspoon of sugar."

Now 2, 3, 1 are arguments — they're the real values you plug into the recipe.
In Code
DEFINING (Writing the recipe)
javascript
function greetUser( firstName ) {
  // firstName is a PARAMETER
  // It's a placeholder — we don't know yet who we're greeting
  return "Hello, " + firstName;
}
CALLING (Cooking with real numbers)
javascript
// Calling the function
greetUser( "Alice" );
// "Alice" is an ARGUMENT
// Now we're being specific!

// Result:
// "Hello, Alice"
When? What are they? Nature Example
DEFINE Parameters Placeholders firstName in function(firstName)
CALL Arguments Real values "Alice" in greetUser("Alice")
💡 KEY: A parameter is the name. An argument is the value. Parameters go in the definition. Arguments go in the call.
Three Real Examples
Example 1: User Login
javascript
function login( email, password ) {
  // email, password = PARAMETERS
  return database.checkUser(email, password);
}

// When we call it:
login( "alex@mail.com", "secret123" );
// "alex@mail.com", "secret123" = ARGUMENTS
Example 2: Calculate Discount
python
def apply_discount( price, percent ):
  # price, percent = PARAMETERS
  return price * (1 - percent)

# When we call it:
apply_discount( 100, 0.20 )
# 100, 0.20 = ARGUMENTS
# Result: 80 (20% off)

Function Signature

What Is a Signature?
🆔 Analogy: Bank Account ID Card
When you open a bank account, the bank issues an ID card showing:

• Your name (who you are)
• Your account number (unique ID)
• Authorized activities (what you can do)

A function signature is similar. It shows:

• The function name (who it is)
• What parameters it expects (what inputs it needs)
• What it will return (what it outputs)
Breaking Down a Signature
javascript
function calculateTax( salary, taxRate ) {
   └─ This entire line is the SIGNATURE
The function name
calculateTax

This is how you call the function. When you need to do something, you say "calculateTax".
The parameters
( salary, taxRate )

These are the inputs the function expects. Someone must provide these values when calling it.
💡 KEY: The signature is a contract. It tells the rest of the code: "Call me calculateTax and give me two things: a salary and a taxRate."
Why Signatures Matter
If you change the signature, all code that calls the function will break:
❌ The Problem
javascript
// OLD signature:
function getUser( userId ) { ... }

// Lots of code uses it this way:
getUser(42);
getUser(108);
getUser(200);

// Now someone changes the signature:
function getUser( userId, includeProfile ) { ... }
                      ↑ NEW parameter added!

// ❌ Now all the old getUser(42) calls BREAK!
// The function expects 2 arguments but only got 1
⚠️ REMEMBER: The signature is a promise. If you change it in a team, you must update every place that calls it. Otherwise, the app breaks.

Function Body

What Happens Inside?
📋 Analogy: Recipe Steps
A recipe card has two parts:

Ingredients list: "flour, eggs, sugar"
This is like the signature

Steps to follow: "Mix flour and sugar. Add eggs one-by-one. Bake for 30 min."
This is like the body

The body is where the actual work happens. It's all the code inside the curly brackets { }.
The Body Contains
Decision Logic

if/else statements that check conditions 
if (age >= 18) {
  allowAccess();
}
Calculations

Math operations on the parameters 
let total = price * 1.1;
return total;
Loops

Repeat actions multiple times 
for (let i=0; i<5; i++) {
  doSomething();
}
Return Statement

Send a result back to the caller 
return result;
// Function stops here
Complete Example
Example: Validate Email
javascript
function validateEmail( email ) {
  // ═══════ FUNCTION BODY STARTS ═══════

  // LOGIC: Check if email is empty
  if (!email || email === "") {
    return false;  // Invalid!
  }

  // LOGIC: Check if email has @ symbol
  if (!email.includes("@")) {
    return false;  // Invalid!
  }

  // If we got here, it's valid
  return true;

  // ═══════ FUNCTION BODY ENDS ═══════
}
💡 KEY: The body is everything between the curly brackets { }. It's the actual work. No body = no work. No return statement = no result sent back.

Logic

What Is Logic?
🧠 Analogy: Making Decisions
Every day you make decisions:

"Should I go outside?"

You check: If weather is sunny AND temperature > 18°C,
THEN go outside. ELSE stay inside.

That checking + deciding = LOGIC.

In code, logic is the same thing: Check conditions, make decisions.
Three Types of Logic
Type 1: Conditional (if/else)
javascript
if (score >= 50) {
  studentPasses = true;
} else {
  studentPasses = false;
}
Check a condition. If true, do one thing. If false, do another.
Type 2: Validation (checking requirements)
javascript
if (!email.includes("@")) {
  return "Email is invalid";
}
Check if data meets requirements. If not, reject it.
Type 3: Loop (repeat with conditions)
javascript
while (attempts < 3) {
  askPassword();
  attempts++;
}
Keep repeating while a condition is true. Stop when it's false.
💡 KEY: Logic is the reasoning inside your code. It asks: "Should I do this? Check that? Keep repeating?" That's logic.
Logic Can Be Broken
❌ Wrong Logic
javascript
function validatePassword( pwd ) {
  if (pwd.length >= 8) {
    return true;  // Password is strong
  }
  return false;   // Too short
}
❌ PROBLEM: Only checks length. A password "12345678" is 8 characters, but it's terrible (no letters, no symbols)!
✓ Better Logic
javascript
function validatePassword( pwd ) {
  const hasLength = pwd.length >= 8;
  const hasNumbers = /[0-9]/.test(pwd);
  const hasSymbols = /[@#$]/.test(pwd);

  if (hasLength && hasNumbers && hasSymbols) {
    return true;  // Strong password!
  }
  return false;   // Not strong enough
}
✓ BETTER: Checks 3 things. Only accepts passwords with length AND numbers AND symbols.

Return Type

What Is a Return Type?
📦 Analogy: Delivery Package Label
When a package arrives at your door, it has a label:

"CONTENTS: Electronics"
"WEIGHT: 2 kg"
"FRAGILE: Yes"

The label is a promise. You expect electronics, not socks. You handle it gently.

A return type is the same. It's a promise: "When you call me, I will give you back a ___."

If you promise a NUMBER but return TEXT, the app breaks. The receiver expected one thing, got another.
Common Return Types
Return Type What It Means Example Code What You Get Back
number A number return 42; 42
string Text return "Hello"; "Hello"
boolean true or false return true; true
array A list return [1,2,3]; [1, 2, 3]
object A data structure return {name: "Alex"}; {name: "Alex"}
How to Declare Return Type
In TypeScript (the safer version of JavaScript), you declare what you promise to return:
TypeScript Example
typescript
function calculateAge( birthYear: number ) : number {
  // ↑ I promise to return a NUMBER
  return 2024 - birthYear;
}
The : number at the end is the return type declaration. It says: "I promise this function will always return a number."
When Return Types Break
❌ Broken Promise
typescript
function getTotal( ) : number {
  return "Total: $100";  // ❌ Returned TEXT, not NUMBER!
}

// Somewhere else in the code:
let price = getTotal();
let newPrice = price + 50;  // ❌ Can't add 50 to text! BREAKS!
The function promised a number but returned text. Other code expected a number and tried to do math with it. Crash!
⚠️ REMEMBER: Return type is a contract. If you promise number, always return a number. If you promise boolean, always return true or false. Breaking the promise breaks the app.

Six Action Verbs

Overview: How to Modify Code
There are 6 ways developers change code. Each one uses a specific verb:
① ADD — Insert new things
② REMOVE — Delete old things
③ PASS — Send values to functions
④ MODIFY — Change what exists
⑤ REFACTOR — Rewrite for quality
⑥ VALIDATE — Check if data is correct
① ADD — Adding New Things
Scenario: Need a New Parameter
BEFORE
javascript
function sendEmail( to ) {
  mailer.send(to);
}
AFTER (Added parameter)
javascript
function sendEmail( to, subject ) {
  mailer.send(to, subject);
}
We added a new parameter subject so the function can now send subject lines. The signature changed, but the purpose stayed the same: send email.
② REMOVE — Deleting Things
Scenario: Unused Parameter
BEFORE
javascript
function createUser(
  name, age, tempID
) { ... }
tempID is never used inside the function. Why is it there?
AFTER (Removed parameter)
javascript
function createUser(
  name, age
) { ... }
Cleaner. Now developers know exactly what data the function needs.
③ PASS — Sending Values
Scenario: Calling a Function with Arguments
javascript
// The function expects values:
function multiply( a, b ) {
  return a * b;
}

// We PASS the values when calling:
multiply( 5, 3 );
           ↑ We PASS 5 and 3 as arguments
"PASS" means send arguments to a function. We pass the values that the parameters will receive.

Action Verbs (Part 2)

④ MODIFY — Changing What Exists
Scenario: Business Rule Changed
BEFORE
javascript
function applyDiscount( price ) {
  return price * 0.90;
  // 10% off everything
}
AFTER (Modified logic)
javascript
function applyDiscount( price ) {
  if (price > 100) {
    return price * 0.80; // 20%
  } else {
    return price * 0.90; // 10%
  }
}
We modified the discount logic. The function name stayed the same, parameters stayed the same, but the logic inside changed. Big items now get 20% off instead of 10%.
⑤ REFACTOR — Rewriting for Quality
Scenario: Cleaning Up the Code
BEFORE (Hard to read)
javascript
function checkPass(s) {
  if (s >= 50 && s <= 100) {
    return true;
  } else {
    return false;
  }
}
AFTER (Clean & readable)
javascript
function checkPass(score) {
  return score >= 50 && 
         score <= 100;
}
We refactored the code. Same result, better quality. The function still checks if a score passes, but now it's much cleaner. Variable names are better, the logic is simpler.
💡 REFACTOR = Same what, different how. The function still does the same thing, but the code looks better and is easier to understand.
⑥ VALIDATE — Checking If Data Is Correct
Scenario: Making Sure Input Is Good
javascript
function submitForm( name, email, age ) {
  // VALIDATE: Is name empty?
  if (!name || name === "") {
    return "Name is required!";
  }

  // VALIDATE: Does email have @?
  if (!email.includes("@")) {
    return "Email must have @";
  }

  // VALIDATE: Is age positive?
  if (age < 0) {
    return "Age can't be negative";
  }

  // All checks passed! Save the data.
  database.save({ name, email, age });
  return "Success!";
}
We validate each piece of input. We check multiple requirements. Only if all checks pass do we save the data.
⚠️ VALIDATE = Check multiple rules before accepting data. Bad input = rejected. Good input = accepted.

Putting It All Together

Watch a Complete Function Work
Real-World Example: User Registration
typescript
function registerUser( email, password )
                  └─ SIGNATURE (the contract)

  // ═══════ BODY STARTS ═══════

  // VALIDATE: Is email valid?
  if (!email.includes("@")) {
    return { success: false };
  }

  // VALIDATE: Is password strong?
  if (password.length < 8) {
    return { success: false };
  }

  // LOGIC: Both checks passed, save user
  database.save({ email, password });

  // RETURN: Promise to send back an object with success:true
  return { success: true };
           └─ RETURN TYPE: object

  // ═══════ BODY ENDS ═══════
}
Trace the Execution
Let's watch what happens when we call this function:
Step 1: Make the Call
registerUser("daniel@school.com", "SecurePass123")

→ Function starts running
Step 2: Parameters Receive Arguments
email = "daniel@school.com"
password = "SecurePass123"

→ Now the function knows what to work with
Step 3: Execute Logic #1 (Email Check)
Does "daniel@school.com" include "@"?

✓ YES

→ Validation PASSES, continue to next check
Step 4: Execute Logic #2 (Password Check)
Is "SecurePass123" at least 8 characters?

✓ YES (14 characters)

→ Validation PASSES, both checks succeeded
Step 5: Save Data
database.save({ email: "daniel@school.com", password: "SecurePass123" })

→ User is now saved in the database
Step 6: Return Result
return { success: true }

→ Function is DONE. Result goes back to caller.
💡 REMEMBER: Every function follows this journey: 1) Receive parameters 2) Execute logic 3) Return result. Master these 6 concepts, and you master functions.
